# Main-text figure generators (Figures 1-9)

Each `Figure_N/` folder except `suppl_FigS6_stub/` is a standalone, two-step pipeline:

1. `python 01_generate_data.py` -- runs the simulation/computation and writes
   every numeric result to `Figure_N/data/`. No plotting code.
2. `python 02_make_figure.py` -- reads only the cached files in `data/` and
   draws the figure. Writes the image directly to `../figures/FigN.pdf` (PNG
   for Figure 5; Figures 8 and 9 also write their own 600-dpi TIFF), plus a
   low-resolution preview inside the folder and the manuscript caption text.
   Never re-simulates.

`suppl_FigS6_stub/` is a documentation-only stub: that figure is produced by
`supplementary_figures/suppl_FigS6/`'s own pipeline (part of the shared 195-protocol
production run) and copied into `../figures/Fig2.pdf`/`.tiff`. See
`suppl_FigS6_stub/README.md`.

Most `01_generate_data.py` scripts accept `--workers N` to parallelize across
parameter cells, and a `--smoke` flag for a fast end-to-end check with small
replicate counts and a short time horizon.

| Folder | Figure | Content |
|---|---|---|
| `maintext_Fig1/` | 1 | Root-centered bookkeeping in one physical active transmission forest |
| `suppl_FigS6_stub/` | 2 | Event-level verification of the four ABM intensity terms (documentation stub; generated by `supplementary_figures/suppl_FigS6/`) |
| `maintext_Fig2/` | 3 | Constant-pool ABM vs. QSS comparison |
| `suppl_FigS1/` | 4 | Perturbation-expansion scale and accuracy |
| `maintext_Fig3/` | 5 | Growth rate and R_time control boundary |
| `suppl_FigS7/` | 6 | Ensemble-mean local closure validation |
| `maintext_Fig4/` | 7 | Closure-trajectory validation against the ensemble-mean ABM |
| `suppl_FigS8/` | 8 | Representative R=4 trajectories vs. the depth-K dynamic closures (Sect. 7.7) |
| `maintext_Fig5/` | 9 | Representative R=4 trajectories vs. the zeroth-order algebraic QSS closure (Sect. 7.7) |

`suppl_FigS8/` and `maintext_Fig5/` share the finite-pool ABM engine and closure
solvers in `shared_trajectory_engine/trajectory_core.py` (same engine and master
seed 20260815 as Figures 6 and 7 -- their R=4 ABM replicates are verified
bit-for-bit identical to Figure 7's cached data).

`GENERATION_REPORT.md` records the production run that produced the current
`../figures/Fig1.pdf`-`Fig9.pdf` (commands, output SHA-256 hashes, and
numerical/structural checks per figure). `audit_manuscript_figures.py`
independently checks a compiled `manuscript.pdf` for exactly one caption per
figure number; it is not needed to regenerate the figures themselves.

`make_bmb_tiffs.py` (needs `PyMuPDF` and `Pillow`; run after the
`02_make_figure.py` scripts have populated `../figures/`) produces the 600-dpi
LZW-compressed `../figures/FigN.tiff` submission copies that Bulletin of
Mathematical Biology requires for combination artwork -- pdfLaTeX cannot
embed `.tiff` directly, so these are separate journal-upload files, not
something `manuscript.tex` includes. See the top-level `README.md` for
details.

## Reproducing from scratch

Each folder has its own `requirements.txt`. From each `Figure_N/`:

```
pip install -r requirements.txt
python 01_generate_data.py --workers 8
python 02_make_figure.py
```
